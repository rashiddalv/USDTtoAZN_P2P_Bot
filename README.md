# Binance P2P USDT/AZN Alert Bot

Telegram-бот на **Node.js + TypeScript**, который каждые 30–60 секунд проверяет публичные объявления
**Binance P2P** по паре **USDT/AZN** и присылает уведомление, когда появляется контрагент, готовый
**купить ваш USDT** по курсу **≥ заданного порога** (по умолчанию `1.70 AZN`).

Направление: **вы отдаёте USDT → получаете AZN**. Бот только уведомляет, сделки не совершает,
доступ к аккаунту Binance и API-ключи не нужны.

## Как это работает

```
┌──────────────┐  каждые N сек   ┌─────────────────────┐   POST /adv/search    ┌──────────────┐
│   Monitor    │ ───────────────▶│ BinanceP2PService   │ ─────────────────────▶│  Binance P2P │
│ (фоновый     │                 │ timeout / retry /   │ ◀───────────────────── │  (web API)   │
│  цикл)       │ ◀───────────────│ backoff / 429       │        JSON            └──────────────┘
└──────┬───────┘   P2PAd[]       └─────────────────────┘
       │ price >= minRate и ещё не уведомляли
       ▼
┌──────────────┐    sendMessage   ┌──────────────┐
│  StateStore  │                  │  Telegram    │
│ data/state.  │ ◀──────────────▶ │  Bot (grammY)│ ◀── /start /status /rate /check
│ json         │                  └──────────────┘
└──────────────┘
```

- **Monitor** — независимый фоновый цикл. Работает всегда, вне зависимости от того, пишете ли вы боту.
- **BinanceP2PService** — единственное место, где есть знание о Binance endpoint.
- **StateStore** — маленькое JSON-хранилище (`data/state.json`): текущий порог, ID уже отправленных
  объявлений, статистика. Переживает перезапуск.
- **Telegram bot** — принимает команды только от `TELEGRAM_ALLOWED_USER_ID`, остальным отвечает `Access denied.`

## Важно про Binance P2P endpoint

У Binance **нет официального публичного REST API для P2P-объявлений**. Бот использует endpoint, который
вызывает сам веб-интерфейс `p2p.binance.com`:

```
POST https://p2p.binance.com/bapi/c2c/v2/friendly/c2c/adv/search
{ "asset": "USDT", "fiat": "AZN", "tradeType": "SELL", "page": 1, "rows": 20, "payTypes": [], "publisherType": null }
```

Проверено **2026-09-09**:

| Запрос `tradeType` | Что возвращает                                                   | `adv.tradeType` в ответе | Цены (на момент проверки) |
| ------------------ | ---------------------------------------------------------------- | ------------------------ | ------------------------- |
| `SELL`             | объявления контрагентов, которые **покупают** USDT (вы продаёте) | `BUY`                    | 1.66–1.67 AZN             |
| `BUY`              | объявления контрагентов, которые **продают** USDT (вы покупаете) | `SELL`                   | 1.68–1.69 AZN             |

То есть `tradeType` в запросе — это **ваша** сторона сделки. Боту нужна сторона `SELL`.
AZN поддерживается: endpoint вернул ~130 объявлений для USDT/AZN.

Так как endpoint неофициальный, он может измениться без предупреждения. Поэтому:

- вся работа с ним изолирована в `src/services/binanceP2P.service.ts` и типизирована в
  `src/services/binanceP2P.types.ts`;
- остальной код зависит только от интерфейса `P2PAdsProvider` и нормализованного типа `P2PAd`;
- при неожиданном формате ответа объявления пропускаются с предупреждением в логе, процесс не падает;
- есть таймаут, retry с exponential backoff + jitter, cooldown при `429`, замедление опроса при серии ошибок.

Чтобы заменить источник данных, реализуйте `P2PAdsProvider` и подставьте его в `src/index.ts`.

## Что нужно сделать вручную

Это единственные два шага, которые нельзя автоматизировать:

### 1. Создать Telegram-бота

1. Откройте в Telegram [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot`, задайте имя и username (должен заканчиваться на `bot`).
3. Скопируйте токен вида `123456789:AAF...` — это `TELEGRAM_BOT_TOKEN`.
4. (Необязательно) `/setprivacy` → `Disable` не требуется, бот работает в личных сообщениях.

### 2. Узнать свой Telegram User ID

1. Откройте [@userinfobot](https://t.me/userinfobot) (или [@getmyid_bot](https://t.me/getmyid_bot)) и нажмите **Start**.
2. Бот покажет `Id: 123456789` — это `TELEGRAM_ALLOWED_USER_ID`.

### 3. Нажать Start у своего бота

Telegram не даёт ботам писать первыми. После запуска откройте своего бота и отправьте `/start`
один раз — после этого уведомления будут приходить автоматически.

## Запуск локально

Требуется **Node.js ≥ 20** (проверено на 24.x).

```bash
# 1. Установить зависимости
npm install

# 2. Создать .env и заполнить TELEGRAM_BOT_TOKEN и TELEGRAM_ALLOWED_USER_ID
cp .env.example .env          # Windows PowerShell: Copy-Item .env.example .env

# 3. (опционально) Проверить, что Binance отдаёт объявления, без Telegram
npm run probe

# 4a. Режим разработки (hot reload, читаемые логи при LOG_FORMAT=pretty)
npm run dev

# 4b. Production
npm run build
npm start
```

После старта в логе появится `telegram bot started` и `monitor started`, затем каждые
`POLL_INTERVAL_SECONDS` — `check completed` с количеством объявлений и лучшим курсом.

Остановка — `Ctrl+C`: бот корректно завершает опрос, останавливает long polling и сохраняет состояние.

## Запуск в Docker

```bash
cp .env.example .env    # заполнить токен и user id
docker compose up -d --build
docker compose logs -f
```

Состояние хранится в volume `bot-data` (`/data/state.json` внутри контейнера), так что порог и список
уже отправленных объявлений переживают `docker compose restart` и пересборку образа.

Без compose:

```bash
docker build -t p2p-azn-bot .
docker run -d --name p2p-azn-bot --restart unless-stopped --env-file .env -v p2p-data:/data p2p-azn-bot
```

## Команды бота

| Команда       | Описание                                                                                                   |
| ------------- | ---------------------------------------------------------------------------------------------------------- |
| `/start`      | Описание бота и текущие настройки                                                                          |
| `/status`     | Работает ли мониторинг, порог, пара, время последней успешной проверки, число объявлений, ошибки, cooldown |
| `/rate 1.705` | Изменить минимальный курс без перезапуска. Валидация: число в диапазоне 0.5–10, до 4 знаков после запятой  |
| `/rate`       | Показать текущий порог                                                                                     |
| `/check`      | Немедленно выполнить проверку и показать лучшие предложения (подходящие или, если их нет, топ по курсу)    |
| `/help`       | Как работает бот, команды и ссылки                                                                         |

## Интерфейс бота и ссылки в приложение Binance

Бот работает через inline-кнопки: `/start` открывает меню (проверить, статус, порог, помощь), экраны
редактируются на месте, порог можно менять кнопками ±0.005 / ±0.01 или пресетами без ввода команд.
Сообщения используют HTML-разметку и моноширинные блоки, чтобы цифры выравнивались на телефоне.

В каждом уведомлении и в списке `/check` есть две ссылки:

| Кнопка                  | URL                                                          | Поведение                                                                                                                                               |
| ----------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 📱 Открыть в приложении | `https://app.binance.com/...?_dp=<base64>`                   | На iOS и Android открывает приложение Binance (universal/app link) и показывает страницу трейдера внутри него. Без приложения падает на www.binance.com |
| 🌐 В браузере           | `https://p2p.binance.com/en/advertiserDetail?advertiserNo=…` | Обычная веб-страница                                                                                                                                    |

Как это устроено (проверено 2026-09-09):

- `app.binance.com/.well-known/apple-app-site-association` объявляет `paths: ["*"]` для приложения Binance,
  а `p2p.binance.com` только `/oauth/authorize`. Поэтому в приложение на iOS ведёт только домен `app.binance.com`.
- `assetlinks.json` на `app`/`www`/`p2p.binance.com` объявляет `handle_all_urls` для `com.binance.dev` (Android).
- Параметр `_dp` содержит base64 внутреннего deep link. Используется универсальный маршрут
  `/webview/webview?type=default&url=<base64 url>`, который открывает любую страницу Binance внутри приложения.
  Этот же формат Binance встраивает на p2p.binance.com и документирует для Binance Pay.
- Telegram допускает в inline-кнопках только `http(s)`/`tg` ссылки, поэтому схема `bnc://` не используется.

Нюанс: если в Telegram включён встроенный браузер, iOS сначала откроет ссылку в нём. Отключите
«Открывать ссылки в приложении» в настройках Telegram, и приложение Binance будет открываться сразу.
Логика ссылок изолирована в `src/services/binanceLinks.ts`.

## Переменные окружения

См. `.env.example`. Все значения, кроме двух первых, имеют разумные значения по умолчанию.

| Переменная                 | По умолчанию | Описание                                                                                                            |
| -------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN`       | —            | Токен от BotFather **(обязательно)**                                                                                |
| `TELEGRAM_ALLOWED_USER_ID` | —            | Ваш числовой Telegram ID **(обязательно)**; остальные получают `Access denied.`                                     |
| `MIN_RATE`                 | `1.70`       | Начальный порог. После первого запуска актуальное значение хранится в `state.json` (`/rate`)                        |
| `POLL_INTERVAL_SECONDS`    | `45`         | Интервал опроса. Меньше 30 не допускается (принудительно 30)                                                        |
| `NOTIFIED_TTL_HOURS`       | `24`         | Через сколько часов «не виденное» объявление удаляется из памяти                                                    |
| `CHECK_TOP_N`              | `5`          | Сколько объявлений показывать в `/check`                                                                            |
| `ASSET` / `FIAT`           | `USDT`/`AZN` | Пара                                                                                                                |
| `BINANCE_TIMEOUT_MS`       | `15000`      | Таймаут одного запроса                                                                                              |
| `BINANCE_RETRY_ATTEMPTS`   | `3`          | Попыток на один запрос (backoff 1s → 2s → 4s… + jitter, максимум 20s)                                               |
| `BINANCE_MAX_PAGES`        | `3`          | Максимум страниц (по 20 объявлений); следующая страница запрашивается только если последнее объявление ещё ≥ порога |
| `DATA_DIR`                 | `./data`     | Папка для `state.json`                                                                                              |
| `LOG_LEVEL`                | `info`       | `trace`/`debug`/`info`/`warn`/`error`                                                                               |
| `LOG_FORMAT`               | `json`       | `json` (structured, для production) или `pretty` (для разработки)                                                   |
| `TZ`                       | `Asia/Baku`  | Часовой пояс для времени в сообщениях и логах                                                                       |

`.env` добавлен в `.gitignore` и `.dockerignore`.

## Логика уведомлений и защита от спама

- Объявление подходит, если `price >= minRate` (включительно).
- Для каждого увиденного объявления хранится `{ lastPrice, lastAbove, lastSeenAt, notifiedAt, notifyCount }`.
- Уведомление отправляется, когда объявление подходит **и** либо оно новое, либо на прошлой проверке
  оно **не** подходило (цена впервые пересекла порог снизу вверх). Объявление, которое подходит
  проверку за проверкой, отправляется **один раз**.
- Если доставка в Telegram не удалась, флаг сбрасывается и отправка повторится на следующей проверке.
- Записи, не встречавшиеся дольше `NOTIFIED_TTL_HOURS`, удаляются — хранилище не растёт.
- При изменении порога через `/rate` не требуется перезапуск: новые подходящие объявления придут
  на следующей проверке, уже отправленные повторно не придут.

## Архитектура

```
src/
  index.ts                      — сборка зависимостей, graceful shutdown
  config/index.ts               — загрузка и валидация .env (zod)
  bot/
    bot.ts                      — grammY-бот, access control, команды, отправка алертов
    messages.ts                 — форматирование сообщений (HTML)
  services/
    binanceP2P.service.ts       — интеграция с Binance P2P (единственное место с endpoint)
    binanceP2P.types.ts         — типы ответа Binance + нормализованный P2PAd + P2PAdsProvider
  monitor/
    monitor.ts                  — фоновый цикл опроса, backoff при ошибках, /check
    matcher.ts                  — чистая логика «подходит / уведомлять» (покрыта тестами)
  storage/stateStore.ts         — persistent JSON-хранилище с атомарной записью
  utils/                        — logger (pino), retry, sleep, форматирование
scripts/probe.ts                — быстрый запрос к Binance без Telegram
tests/                          — vitest
```

Стек: `grammy` (Telegram Bot API), `pino` (structured logging), `zod` (валидация конфига), встроенный
`fetch` Node.js, `vitest`, `eslint` + `typescript-eslint` + `prettier`.

## Troubleshooting

| Симптом                                                      | Что делать                                                                                                                      |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| `Invalid environment configuration` при старте               | Проверьте `.env`: токен и `TELEGRAM_ALLOWED_USER_ID` (число).                                                                   |
| Бот отвечает `Access denied.`                                | В `.env` указан не ваш ID. Проверьте через @userinfobot.                                                                        |
| Уведомления не приходят, хотя `/check` показывает совпадения | Убедитесь, что вы нажали `/start` у бота. Проверьте `/status` — там видно число отправленных уведомлений и последнюю ошибку.    |
| В логах `Binance responded 429`                              | Бот сам уходит в cooldown (Retry-After или 60 с) и замедляет опрос. Увеличьте `POLL_INTERVAL_SECONDS`.                          |
| `Binance refused the request (HTTP 403)`                     | WAF/гео-ограничение. Попробуйте с другого IP/сервера. Бот продолжит попытки на следующем цикле.                                 |
| `skipping ad with unexpected shape` в логах                  | Binance изменил формат ответа. Обновите типы в `binanceP2P.types.ts` и `normalize()` в сервисе.                                 |
| Порог 1.70 и ничего не приходит                              | Это нормально: на момент написания лучший курс покупки USDT за AZN был ~1.67. Используйте `/check`, чтобы видеть текущий рынок. |
